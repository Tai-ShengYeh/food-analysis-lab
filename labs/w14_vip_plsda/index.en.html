A question to start with
The model says this wavelength matters most —
do you believe it?
A true story (anonymized): while preparing the materials for this course, a script that computes VIP had one extra .sum() inside its loop, which collapsed “each wavelength’s own contribution” into a single number too early — so all 228 wavelengths received exactly the same VIP value, and the “top 20 VIP wavelengths” the script printed were meaningless.

Three simple checks would have caught this bug:

🟰
All VIP values identical
228 wavelengths should differ — all being the same is a warning sign in itself
➗
mean(VIP²) ≠ 1
VIP is defined so that “the mean of VIP² over all wavelengths = 1”; if you don’t get 1, the formula or the coefficients are wrong
🧪
High VIP does not match the chemistry
If the “most important” bands don’t match any known functional-group absorption, be suspicious instead of copying them down

In this class we will use methods that check themselves and walk through VIP, classification, and outlier judgment again.

First, review W13 PLS ↗

The three letters in a PLS model: w, t, b

  • LV (latent variable): a “composite indicator” PLS builds from the spectra; each LV is related to both the spectra and the concentration
  • w (weights): one set per LV, one number per wavelength = “how much this wavelength counts in this LV”
  • t (scores): the spectrum (after subtracting the mean spectrum) multiplied by w and summed. Example: w=(0.6, 0.8), x=(0.5, 0.25) → t=0.3+0.2=0.5
  • b (regression coefficients): obtained by linking w and q; one b per wavelength, and the sign tells you the direction
Principle 1

VIP: variable importance in projection, each symbol in plain words

VIPj = √( J · Σa SSYa·(wja/‖wa‖)² / Σa SSYa )
  • j = the j-th wavelength; J = total number of wavelengths (written p in the NB12 code; J=81 here); a = the a-th LV
  • SSYa = qa²·Σta² = the y variance explained by the a-th LV (lowercase q is the slope of y on t, unrelated to the Q residual later)
  • (wja/‖wa‖)² = the share of wavelength j in the weights of the a-th LV; the shares within each LV sum to 1
  • In plain words: VIP² = J × “the share across LVs, weighted-averaged by SSY” — a wavelength with a big share in the LV that explains the most y gets a high VIP
  • Shares sum to 1 → the mean of VIP² over all wavelengths is exactly 1 → VIP>1 = above average (a rule of thumb, not a test)
  • Share of y variance explained by the 4 LVs in NB12: 84.5% / 13.6% / 1.6% / 0.3% — the first LV pretty much decides everything

VIP ≠ direction

VIP has no sign; the coefficient b does

NB12VIPCoefficient b
1200 nm (acetic acid C–H, illustrative)2.57+4.96
1450 nm (water O–H first overtone, illustrative)1.82-4.01
  • Both bands have VIP >1: both are important
  • b is one positive and one negative: holding the other inputs fixed, a higher input at 1200 nm raises the predicted concentration, while at 1450 nm (water) it does the opposite; how the actual spectra change with concentration must be checked in the data separately — it can’t be read directly from b
  • To talk about “direction”, always look at b; VIP only answers “how important”

Selection bias

Using the same data to select wavelengths and score them = setting your own exam and grading it

❌
Select and evaluate on the same data
Compute VIP and pick wavelengths from all the data, then score on the same data — the model has peeked at the answers, so the score is optimistic
✅
Select on the calibration set only
Compute VIP using only the calibration (training) set; after filtering, compute RMSEP once on a test set that has never been touched
🔁
Or re-select within each fold
In cross-validation, recompute VIP and re-filter in every fold so that RMSECV is fair
What NB12 did: VIP was computed on the 60 training samples, and RMSECV (after filtering) was also computed on the same training samples → this is “select and evaluate on the same data”, so beware of optimistic bias; RMSEP uses 20 test samples never touched → fair, but there are too few samples. The VIP>1 threshold was set in advance, not tuned by looking at RMSEP.

  • One-hot: 6 oils → 6 columns of 0/1, and the column of the class it belongs to is 1 (column order follows NB12: alphabetical by English code)
  • argmax: the model gives a score ŷ for each of the 6 columns, and the column with the largest score is the answer
  • ŷ is not a probability: it can be negative or exceed 1, and is only used for comparing sizes

Codes: CAN = canola oil, COC = coconut oil, EVOO = extra virgin olive oil, PEA = peanut oil, ROO = refined olive oil, SOY = soybean oil.

Classification ②

PLS-DA: turning a classification problem into regression

  • y changes from “one concentration” to “6 one-hot columns”; PLS regresses all 6 columns at once (the same PLS as in W13)
  • The number of LVs is again chosen by cross-validation: NB12 picked 6 LVs
  • Each new sample gets 6 ŷ values → argmax decides the class
  • Finally, the test-set results are summarized in a confusion matrix (next two pages)
The six-oil data in NB12: 6 oils × 15 samples = 90; 30% were drawn as the test set, stratified by class (27 samples), and the remaining 63 were used to build the model.

Orange has no PLS-DA widget; the beginner route does the same thing with “PCA scores + logistic regression” (next page).
Classification ③ Orange route

PCA scores + logistic regression: scores → probability

  • Compress first: PCA condenses 70 wavelengths into 6 scores (W12 PCA ↗), and the classifier sees only these 6 numbers
  • Logistic regression: add up the weighted scores to get z; the S-curve p = 1/(1+e−z) in the figure is the demo for two-class problems (a single sigmoid is used only when there are two classes)
  • The six oils need multinomial logistic regression: one zk per class, normalized together by softmax into probabilities pk = exp(zk)/Σexp(zj), the six probabilities sum to 1, and the largest class is chosen — the same idea as argmax
  • C=100: the strength of regularization (keeping the weights from getting too large); the larger C is, the weaker the restriction and the more closely the model fits the training data
Orange OR14 part 1

Six-oil classification: File → PCA → Logistic Regression → Confusion Matrix

  • PCA: set the number of components to 6 and leave Normalize unchecked (spectra share the same unit, so no standardization is needed); connect Transformed Data to Test and Score
  • Test and Score uses 5-fold cross-validation; but PCA was fitted on all 90 samples before being connected — so the validation folds have effectively seen that PCA (data leakage) and CA will be optimistic; use the independent NB12 test set for the formal evaluation (PLS-DA 24/27 = 88.9%)

Outliers ①

Hotelling T²: how far from the center within the model

  • T² = Σ ta² / λa: ta = the sample’s score on the a-th PCA principal component; λa = the variance of the calibration set on that component (eigenvalue, W12 PCA ↗)
  • In plain words: use each component’s own width as the ruler — one step in a narrow direction is more “abnormal” than one step in a wide direction (B is farther than A)
  • 95% limit: an ellipse computed from the F distribution, with about 95% of normal samples falling inside; NB12 (40 calibration samples, 2 principal components) uses the approximate limit k(n−1)/(n−k)·F = 6.66
  • Strictly speaking, this limit is for the calibration set itself; for new samples multiply it by (n+1)/n, about 6.83 — the difference is small and the outlier conclusions don’t change
Outliers ②

Q residual (SPE): how far from the model plane

  • Q = Σ(x − x̂)²: x̂ = the spectrum “reconstructed” by the model from the principal components; the difference is the part the model cannot explain
  • Example: residuals at three wavelengths [0.01, −0.02, 0.02] → sum of the three squared residuals Q = 0.0001 + 0.0004 + 0.0004 = 0.0009; this is only a calculation exercise — whether it exceeds the limit must be judged against a limit built from the same model, same wavelengths and same preprocessing, never a limit computed from another model
  • 95% limit (Jackson–Mudholkar approximation): from how much variance the calibration set still has in the discarded principal components, it estimates the Q value that 95% of normal samples will not exceed; NB12 = 0.00118
  • Note: Q (uppercase) is the residual; the lowercase q in the VIP formula is a slope — the two are unrelated
Outliers ③

T² and Q together: four cases

✅
Low T², low Q: normal
Within the calibration range, and the model recognizes this kind of spectrum
📐
High T², low Q: extreme but recognized
The model understands the chemical composition, it is just more extreme than anything in the calibration set. NB12 leverage point: T² = 28.4 (limit 6.66), Q = 0.00091 (limit 0.00118)
🌀
Low T², high Q: the model has never seen this
New variation the model cannot explain (a new impurity, a different instrument). NB12 instrument-change samples: T² = 0.63, 3.17, with Q about 33 times the limit
🚨
High T², high Q: check first
Both extreme and carrying new variation — go back to the spectrum and the sample first, then decide whether it can be used

Orange OR14 part 2

Apply Domain: project new samples onto the calibration-set PCA

  • Applicability domain: a model is reliable only for samples “similar to the calibration set”; Apply Domain transforms all samples using the calibration-set PCA
  • A point far from the center of the calibration cluster on the scatter plot = intuitively a high T² (e.g., leverage_outlier)
  • Orange has no Q residual: an instrument-change sample may look perfectly normal, and you need Colab NB12 to compute Q
  • OR14 uses 3 principal components and NB12 uses 2, so positions in the plot will not reproduce numbers like 6.66 or 28.4 — just look at “who is outside the cluster”
Found an outlier — what now?

Check first, never delete silently

🔍
First go back to the spectrum/sample itself
Bubbles, impurities, a sample placed the wrong way round, a dilution error? Rule out operational problems first, then talk about statistical judgment
🚫
Never delete data silently
Record the reason before deleting; deleting when you can’t find a reason is manufacturing false accuracy (the same principle as W08 Grubbs outliers ↗)
🔁
Re-validate when transferring a model
A model built on one instrument often gives high Q on another instrument — re-check when changing instruments or batches, and do calibration transfer if needed
