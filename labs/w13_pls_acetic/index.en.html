Wine factory production line (14:32–15:53, rapid NIR/FTIR QC) ↗

The core idea of today: wine and vinegar production lines both use spectrometers to screen composition quickly, but the spectrometer itself doesn’t know the “answer” — it is “taught” by a set of samples with known reference values. Today those reference values are the acetic acid results from the W4 manual titration. Systematic bias in the reference method carries straight into the calibration; independent random error in the reference values raises the RMSEP of the validation — this sentence runs through the whole session.

Today’s task: prepare a series of acetic acid standards of known concentration, measure their NIR spectra, use PLS regression to “translate” spectra into concentration, and learn to choose model complexity by cross-validation and report performance honestly on an independent test set.

Calibration set design

Standards must cover the range; the test set must never be used to tune parameters

  • Dilute concentrated vinegar into 14 equally spaced standards (0–10% w/v), plus 2 vinegars (the white vinegar has a W4 titration value)
  • Kennard–Stone (KS) = pick the samples that best span the spectral space as the calibration set: first pick the two most different spectra, then each time pick the sample “farthest from those already selected”
  • KS picks using each sample’s mean spectrum; but when modeling, the 3 cuvette reloads are each saved separately, not averaged, and all 3 are treated as independent rows
  • The 3 spectra of the same sample must go together on the same side; otherwise it is data leakage, and the error looks falsely low
  • Use the test set only once, at the end, to compute RMSEP — never to choose the number of LVs or the preprocessing
NB11/OR13 demo data (16 samples × 3 cuvette reloads):

Calibration set 12 samples (36 spectra), including the 0% and 10% end points + commercial vinegar B
Test set 4 samples (12 spectra): STD-06 (4.62%), STD-08 (6.15%), STD-11 (8.46%), white vinegar (W4 titration) (4.50%)
The white vinegar is always placed in the test set as a “real sample with a known answer” checkpoint; KS decides the rest.
Preparation example (C₁V₁=C₂V₂): to make 100 mL of a 4.00% standard from 9.0% acetic acid: V₁ = 4.00 × 100 ÷ 9.0 = 44.44 mL, then dilute to 100 mL with water.
Interpolation vs. extrapolation

The model is trustworthy only within the concentration range it has seen

  • Interpolation: a new sample falls inside the calibration range (0–10%) — the model has samples nearby to support it, so the prediction is trustworthy
  • Extrapolation: a new sample falls outside the range (e.g., 12%) — the model hasn’t seen it, and the spectrum–concentration relationship may no longer hold
  • So the 0% and 10% end points must stay in the calibration set (blue dots = calibration set, orange triangles = test set, all inside the range); the report must state the applicability domain: this model applies only to 0–10% w/v acetic acid in water
From a calibration curve to the whole spectrum

W07 used one wavelength; today we use the whole spectrum

Calibration curve (one wavelength): A = m·C + b
Used in reverse: C = (A − b) ÷ m

Whole spectrum (many wavelengths):
ŷ = b₀ + b₁x₁ + b₂x₂ + … + bpxp
   = b₀ + Σ bjxj
  • For the calibration curve, R², and RMSE, see W07 Calibration curve and validation metrics ↗
  • ŷ = predicted acetic acid concentration; xj = absorbance at the j-th wavelength; bj = weight (coefficient) of that wavelength; p = number of wavelengths
  • Solving every bj directly is called multiple linear regression (MLR); the W07 handheld Brix meter does exactly this with a few filters
⚠️
Problem: more unknowns than equations
Each demo spectrum has 60 wavelengths (the real InnoSpectra has 228), but the calibration set has only 12 samples (36 spectra).
To solve for 61 or more b values with only 12 “known answers”, MLR has infinitely many solutions, and adjacent wavelengths move almost together (next slide: collinearity).

The fix: don’t solve for 60 b values directly; first condense the spectrum into a few “latent variables” — that is PLS.

Collinearity

When two wavelengths change almost in sync, the coefficients become unstable

  • Absorbances at adjacent wavelengths rise and fall almost together: x₁ ≈ x₂, correlation coefficient r ≈ 1 (for the correlation coefficient see W04 Method comparison ↗)
  • Then many different sets of coefficients are equally accurate on the calibration samples — MLR can’t tell which set is right
  • Pick the wrong set, and a new sample with just a little noise gets its prediction amplified into a large error
  • Instead of solving for each wavelength’s coefficient directly, PLS first merges wavelengths that move together into LVs, so the coefficients are naturally stable
ModelCalibration sample
x₁=0.50, x₂=0.50		New sample
x₁=0.52, x₂=0.50

Both models give 1.00 on the calibration sample (equally accurate); x₁ gains only 0.02 of noise, yet the first model gives 1.02 and the second gives 1.22 — the larger the coefficients and the more their opposite signs cancel, the more the model amplifies noise.

PLS’s solution: latent variables (LV)

Combine the 60 wavelengths by weighted sum into a few new variables

  • LV score t = each wavelength multiplied by its weight w, then summed — like the score in W12 PCA ↗, it is “the sample’s position on the new axis”
  • The weights w make the LV score and the concentration y vary together as much as possible (maximum covariance): PCA asks “where does X vary most by itself?”; PLS asks “where does X move together with y?” — PLS uses the answer y, so it is supervised
  • Today’s model uses only 2 LVs: only a few numbers to estimate, not 60; in the end it can also be rewritten as a coefficient bj for each wavelength (W14 VIP ↗)
Too few / too many LVs

Number of LVs = model complexity; it needs to be just right

📉
Too few LVs: underfitting
The model can’t capture the signal → RMSEC and RMSECV are both high and close to each other; the predicted-vs-reference plot curves systematically, and the residuals show a pattern
📈
Too many LVs: overfitting
The model starts treating noise as signal → RMSEC keeps falling while RMSECV rises again; the number of LVs far exceeds the chemically plausible number of components (acetic acid, water, scattering)
  • RMSEC = error from building the model on the calibration set and predicting that same set (testing itself, so it always keeps getting smaller)
  • RMSECV = cross-validation error (the next two slides explain how): plot RMSECV vs. LV and take the minimum or the first plateau where it begins
What overfitting looks like

The number of LVs controls how many latent variables the model uses: more LVs fit the calibration set more closely (RMSEC↓), but what they fit may be noise, so new samples do worse (RMSECV, RMSEP↑) — for preprocessed input, PLS is still a linear combination; adding LVs does not turn it into a higher-degree polynomial. The 4th-degree curve here is only an analogy for the overfitting idea that “fitting too tightly sacrifices performance on new samples”; it does not mean PLS itself fits a polynomial. How cross-validation works

Each time, leave out one sample as the “examinee”, rotating 12 times

  • Each round leaves out 1 sample (with its 3 spectra), builds the model on the other 11, and predicts the one left out; repeat for 12 rounds to collect 36 predictions made “without the model having seen that sample” → compute RMSECV
  • Splitting a sample’s 3 replicate spectra across both sides = data leakage: the model “recognizes” that cuvette, and RMSECV looks falsely low
  • Orange: Test and Score → Cross validation by feature → sample_id (already set in OR13)

This approach is called leave-one-group-out (grouped by sample_id); it must be run for every number of LVs to draw the RMSECV vs. LV curve.

Water and preprocessing

Choose preprocessing by comparing RMSECV, not by guessing

  • Water gives the strongest NIR signal (the large O–H band near 1450 nm); the acetic acid signal hides beside it, showing up as small changes in the local C–H / O–H shape
  • Reloading the cuvette shifts and tilts the whole spectrum up or down — unrelated to concentration, so it must be removed first
  • SNV = subtract each spectrum’s own mean and divide by its own standard deviation; SG first derivative = take the slope after local polynomial smoothing (W11 Preprocessing ↗)

PLS autoscales by default

Orange’s Scale checkbox: each wavelength is first divided by its own SD

⚖️
What autoscaling does
Each wavelength (each column) first has its own mean subtracted, then is divided by its own standard deviation (SD) — giving every wavelength the same “volume”, so wavelengths with little variation are magnified too.
🔧
On by default in both sklearn and Orange
In sklearn PLSRegression(scale=True) and the Orange PLS widget, Scale is checked by default. NB11 and OR13 both keep the default, so the numbers on both sides match (RMSECV 0.400).
🔁
Different from the W12 PCA advice
W12 PCA ↗ recommends that PCA on spectra usually not autoscale (it magnifies noisy wavelengths). Here PLS uses the software default — don’t mix up the two weeks’ settings.
🧪
Try it yourself
In Orange, uncheck PLS’s Scale (or set scale=False in sklearn) and see whether RMSECV gets larger or smaller — decide by RMSECV again, don’t guess.

How errors are calculated

Residual e = predicted − reference; all four metrics are computed from e

MetricFormulaIn plain words
RMSE√( Σe² ÷ n )On average, how far off (same unit as concentration)
biasΣe ÷ nHow much too high (+) or too low (−) overall
R²1 − Σe² ÷ Σ(y − ȳ)²Proportion of the reference-value variance the model explains (W07 ↗)
RPDSD(ytest) ÷ RMSEPHow many times larger the samples’ own spread is than the error

e = residual; n = number of spectra; y = reference value (W4 titration / prepared concentration); ȳ = mean of the reference values; SD = standard deviation. Computed on the calibration set it is called RMSEC, by cross-validation RMSECV, and on the test set RMSEP.

Small example: 4 residuals e = 0.2, −0.1, 0.1, −0.2

Σe² = 0.04 + 0.01 + 0.01 + 0.04 = 0.10
RMSE = √(0.10 ÷ 4) = √0.025 ≈ 0.158
bias = (0.2 − 0.1 + 0.1 − 0.2) ÷ 4 = 0

bias = 0 does not mean there is no error: positives and negatives cancel out, so look at RMSE and bias together.

RPD describes only the relative performance on this test set: RPD varies with the concentration spread of the test set itself, and this test set has only 4 independent samples, so the number involves some luck; whether the model is truly suitable for “QC quantification” also depends on RMSEP, bias, and the acceptance tolerance, and should be verified with more independent samples — a conclusion can’t rest on the RPD grade alone.
Random error in the reference method raises RMSEP: the standard deviation of a single W4 titration is about 0.05% w/v; if the reference values come from single titrations, RMSEP can hardly be meaningfully smaller than that; if the computed value is far below it, suspect data leakage first. (Systematic bias is a different matter — it shifts the calibration directly and does not go away with more samples; if the reference values are themselves averages of several titrations, this floor also gets smaller.)

A model can’t be applied directly across instruments: a model from instrument A usually shows clear bias on instrument B and must be recalibrated, or use calibration transfer = measure a small set of common samples on both instruments, work out a conversion that “translates” B’s spectra into A’s form, then keep using A’s model.

Safety rules

Glacial acetic acid: corrosive / flammable; cuvette handling

🧪
Glacial acetic acid is corrosive and flammable, with a pungent odor
Work entirely inside the fume hood, wear gloves and safety goggles, and keep away from ignition sources
🧤
When diluting, always add to water
When preparing standards, add the acetic acid slowly to the water and swirl to mix; never the reverse
🔬
Confirm transmission mode for the cuvette first
Be sure to check with the TA which configuration of your group’s NIR supports cuvette transmission measurement; if the light path is installed backwards, the whole batch is wasted
🧴
Rinse the cuvette immediately after use
Prevents acetic acid residue from corroding the cuvette or interfering with the next student’s measurement
